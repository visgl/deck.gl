DeckGL

import {DeckGL} from '@deck.gl/react';
import type {DeckGLProps, OnDeckChange} from '@deck.gl/react';

The root import creates only a standalone Deck. It owns a canvas unless the caller supplies canvas, and sends JSX <deckView> descriptors to deck.gl, merged with the views prop as Native elements describes. Its props are DeckProps, which has no interleaved option.

Provider roots​

Choose an external overlay by import path, not by a runtime provider-selection prop:

import {DeckGL as MapboxDeckGL} from '@deck.gl/react/mapbox';
import {DeckGL as MapLibreDeckGL} from '@deck.gl/react/maplibre';
import {DeckGL as GoogleMapsDeckGL} from '@deck.gl/react/google-maps';

/mapbox always creates MapboxOverlay, /maplibre always creates MapLibreOverlay, and /google-maps always creates GoogleMapsOverlay. They pass interleaved to the overlay unchanged, so the overlay's own default applies: false for MapboxOverlay and MapLibreOverlay, and true for GoogleMapsOverlay. The Mapbox and MapLibre overlays read interleaved only in their constructors, and the Google Maps overlay when it attaches to its map. When the prop changes, the root finalizes the current overlay, which removes it from the map, and creates a new one. onDeckChange receives null and then the new instance, which the application attaches. Provider roots render no host DOM node and use a detached internal registry key, so they are safe inside a map container that must remain child-free.

Each provider entry point exposes its concrete overlay contract:

Entry pointProps and instance
RootDeckGLProps; the instance is Deck
/mapboxMapboxDeckGLProps; onDeckChange receives MapboxOverlay | null
/maplibreMapLibreDeckGLProps; onDeckChange receives MapLibreOverlay | null
/google-mapsGoogleMapsDeckGLProps; onDeckChange receives GoogleMapsOverlay | null

Provider overlay props exclude map-owned configuration such as canvas, parent, device, viewState, initialViewState, and controller. The MapLibre provider also excludes width, height, and gl. Configure those options on the application-owned Mapbox or MapLibre map, and pass the map in map. DeckGL adds its overlay to the map, adds the new one when interleaved recreates it, and removes it when map changes or DeckGL unmounts. map takes a Mapbox or MapLibre Map or a React Map GL MapRef; keep it in React state. Without map, attach the instance from onDeckChange with map.addControl and remove the same control during cleanup. JSX <deckView> descriptors, merged with the views prop, are sent to the overlay, which keeps one view in step with the map camera. See Views beside the map. See Using with maps for complete attachment and shared-context guidance.

Props and lifecycle​

DeckGLProps is the standalone DeckProps surface plus optional React children, onDeckChange, and ref; the instance is Deck. Provider entry points infer their concrete overlay instance in onDeckChange.

The notification runs after configuration and receives null during cleanup. It is a lifecycle notification rather than a callback ref: replacing only its identity does not recreate the root, but later notifications use the replacement.

Every root also accepts a React 19 ref, which receives the same instance as onDeckChange: Deck on the standalone root, or the overlay on a provider or createDeckGL root. The ref is set after configuration, before onDeckChange runs, and receives null on teardown; a callback ref may return a cleanup function instead. When a provider root recreates its overlay, the ref receives null and then the new instance. Replacing the ref moves the current instance to the new ref without recreating the root.

const deckRef = useRef<Deck>(null);

<DeckGL ref={deckRef} layers={layers} />;

On the standalone root, canvas accepts an HTMLCanvasElement or the id of a <canvas> element. An id is resolved with document.getElementById on the client after mount, so the canvas may be rendered in the same commit as DeckGL. An id that does not name a mounted <canvas> throws. Without parent, deck.gl uses the canvas's parent element. The root binds to the element found at mount; to bind a replacement element that reuses the id, pass that element as canvas or remount with a different React key.

Deck event properties such as onClick remain deck.gl callbacks, not React synthetic events.

Removing a prop resets it to deck.gl's default, as React expects: a removed onError stops being called, removed parameters stop applying, and a removed viewState returns the camera to deck.gl's own view state. A prop set to undefined also falls back to deck.gl's default, as it does in React: deck.gl treats an explicit undefined like a prop that was left out (deck.gl#10906). The layers, widgets and effects props are merged with JSX children, so removing one leaves only the JSX elements. Removing views when the tree has no <deckView> restores deck.gl's default view, after which the root leaves deck.gl's views alone, so a widget such as SplitterWidget can set them. The exceptions are the props that only apply at creation.

Effects such as LightingEffect and PostProcessEffect can be JSX children, as components or <deckEffect> elements, or the effects prop, as in @deck.gl/react/legacy. The root merges the two by ID. deck.gl matches effects by ID, as it does widgets, so a new instance with the same ID updates the mounted effect's props, and creating effects during render is fine.

An error thrown while rendering inside a root, including one the renderer raises for an invalid element, is rethrown from the DeckGL component. The nearest error boundary around DeckGL handles it, as it would for any other component, and the framework's development error overlay shows it. An error boundary inside DeckGL catches errors from its own children first; its fallback can only render native elements or null. Errors that deck.gl raises at runtime, such as a layer whose data fails to load, never reach an error boundary; deck.gl passes them to its onError prop, as with @deck.gl/react/legacy.

debug is a deck.gl prop and is passed to Deck or the overlay unchanged. Warnings and traces go through deck.gl's log: root creation, unmounting and each commit log at level 3, and the props of every configure, including prop-only updates, at level 4. Enable them in the browser console with deck.log.enable() and deck.log.level = 3; see Debugging. The @deck.gl/react debugging guide explains how to read these logs alongside deck.gl's.

The renderer registers with React DevTools, so the Components tab shows the <deckLayer>, <deckView>, <deckWidget> and <deckEffect> elements inside each root, with their props and the components that render them.

Props that only apply at creation​

deck.gl reads some props only when it creates its device, canvas or event manager. Changing or removing them after the root is created has no effect, and in development builds the root warns once per prop. To apply a new value, remount DeckGL with a new React key.

PropRead when deck.gl createsChanging it
canvasIts canvasCreates a new root, with a new Deck
interleaved (/mapbox, /maplibre)The overlayCreates a new overlay; see Provider roots
deviceProps, glIts GPU deviceNo effect; dev warning
debugIts GPU deviceNo effect; dev warning
touchAction, eventRecognizerOptionsIts event managerNo effect; dev warning
_typedArrayManagerPropsThe instanceNo effect; dev warning

device and _canvases are not in the table, because deck.gl applies changes to them after creation. A new device replaces the GPU device, and _canvases updates the canvases of a Deck created in multi-canvas mode. A DeckGL root always renders to its own canvas, which multi-canvas mode does not allow, so to draw one Deck into several canvases, create it with _canvases: [] and use DeckCanvas from @deck.gl-community/react.

id names a canvas that deck.gl creates. The standalone root renders its own canvas, whose id follows id, as Root DOM and sizing describes.

Root DOM and sizing​

Without a canvas prop, the standalone root renders the same wrapper and canvas as @deck.gl/react/legacy:

<div id="deckgl-wrapper" style="position: absolute; z-index: 0; left: 0; top: 0; width: 100%; height: 100%">
  <canvas id="deckgl-overlay" style="left: 0; top: 0"></canvas>
</div>

The ids derive from the id prop: id="map" renders map-wrapper and a canvas with id map. Give each root a distinct id when a page has more than one. The wrapper fills its nearest positioned ancestor by default. width and height size the wrapper, style applies to the wrapper except mixBlendMode, which applies to the canvas, and the canvas fills the wrapper. With a caller-supplied canvas, the root renders no DOM and forwards width, height, and style to deck.gl unchanged. Provider roots never render DOM.

Custom compatible overlays​

For a compatible overlay not covered by the provider roots, bind its factory once:

import {createDeckGL} from '@deck.gl/react';

const DeckGL = createDeckGL({
  createExternalOverlay: props => new MyCompatibleOverlay(props)
});

The factory runs only when the root is initially configured. It is not a render prop and never reaches setProps. The result must implement deck.gl's setProps and finalize lifecycle. See Using with custom overlays for the overlay requirements and host attachment.

recreateOverlayOnChange lists props that the overlay reads only at construction or attach time. When one of them changes (compared with Object.is), the component finalizes the overlay and calls the factory again with the full props. onDeckChange receives null and then the new instance. The provider roots declare recreateOverlayOnChange: ['interleaved'].

forwardViews: true sends <deckView> children, merged with the views prop, to the overlay. Set it for an overlay that renders deck.gl views beside its map, as the provider roots do. Without it, the overlay receives only its views prop.

attach(map, overlay) gives the root a map prop. It attaches the overlay to map and returns a function that detaches it. The root calls it for each overlay it creates while map is set, and calls the returned function before replacing or finalizing the overlay, when map changes or becomes null, and on unmount. Both steps must be safe to repeat, because a Strict Mode replay can call them twice. map is never passed to the overlay. The provider roots attach with map.addControl. See Attach to the host.

const DeckGL = createDeckGL({
  createExternalOverlay: props => new MyCompatibleOverlay(props),
  recreateOverlayOnChange: ['interleaved']
});

Recreating an overlay discards its internal state, such as the hovered object.

Advanced reconciler APIs​

@deck.gl/react/reconciler exports createRoot and unmountAtNode for direct integration. These are advanced APIs; normal applications should use one of the entry points above.
