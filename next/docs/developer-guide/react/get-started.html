Get started

@deck.gl/react renders deck.gl in a React client tree. The root exports DeckGL, and subpaths named after deck.gl's modules export a component for each built-in layer, view, widget and effect.

1. Install the packages you use​

Install React, the renderer, and the deck.gl packages used by the application:

npm install react react-dom @deck.gl/react @deck.gl/core @deck.gl/layers

The renderer requires React 19.2 or later, and TypeScript 5.3 or later for its types. Each component subpath needs its deck.gl package, such as @deck.gl/layers for /layers. The standalone root imports no provider package. Add the matching deck.gl provider and host-map SDK only when using a provider root:

# Mapbox provider root
yarn add @deck.gl/mapbox mapbox-gl

# MapLibre provider root
yarn add @deck.gl/maplibre maplibre-gl

The application owns the Mapbox or MapLibre map; keep map creation in browser-only code. A bundled MapLibre GL JS 6 application calls setWorkerUrl before it creates the first map. See Using with maps for safe overlay attachment and Configure the MapLibre worker for worker and CSP guidance.

2. Render on the client​

The native root creates a browser renderer. In an application that uses React Server Components, put 'use client' at the beginning of the module that imports DeckGL, or import it from an existing client-marked module. This React directive marks that module and its transitive dependencies as client code; Next.js is one framework that supports it. In traditional SSR without React Server Components, initialize a map or overlay after hydration in an effect. Server rendering a DeckGL root does not require ssr: false: the standalone root renders its wrapper and canvas markup, provider roots render no markup, and deck.gl or the overlay is created only after hydration.

3. Size a standalone root​

Without a canvas prop, DeckGL renders a wrapper and canvas like @deck.gl/react/legacy: the wrapper is absolutely positioned with width and height of 100% by default, so it fills the nearest positioned ancestor. Give that container a size in application CSS, or set width, height, or style on DeckGL. See Root DOM and sizing. Supplying canvas tells the component to use a canvas you render and size yourself; it then renders no wrapper or canvas.

4. Add layers​

Import a layer component from the subpath named after its deck.gl module, and pass it the layer's props. deck.gl matches layers by id. A layer without one gets an id from its place in the React tree, so give layers in a changing list a key, and give an id to any layer that other code refers to. See Ids.

import {DeckGL} from '@deck.gl/react';
import {ScatterplotLayer} from '@deck.gl/react/layers';

type Point = {coordinates: [number, number]};

export function App({data}: {data: Point[]}) {
  return (
    <DeckGL initialViewState={{longitude: -122.4, latitude: 37.8, zoom: 12}} controller>
      <ScatterplotLayer id="points" data={data} getPosition={d => d.coordinates} getRadius={100} />
    </DeckGL>
  );
}

Props are checked against ScatterplotLayerProps, and the accessors are typed by the data type, which is inferred from data or passed as <ScatterplotLayer<Point>>. The component builds a new layer on every render, and deck.gl updates only what changed.

Use ordinary React components to organize a map. A component can load its own data with hooks and return one or more layers:

function Airports() {
  const airports = useAirports();
  return <ScatterplotLayer id="airports" data={airports} getPosition={d => d.coordinates} />;
}

<DeckGL initialViewState={INITIAL_VIEW_STATE} controller>
  <Airports />
</DeckGL>;

5. Add views, widgets and effects​

Views and effects come from /core, and widgets from /widgets:

import {LightingEffect, MapView} from '@deck.gl/react/core';
import {ZoomWidget} from '@deck.gl/react/widgets';

<DeckGL initialViewState={INITIAL_VIEW_STATE} controller>
  <MapView id="main-map" />
  <ZoomWidget id="zoom" />
  <LightingEffect ambient={ambientLight} />
  <Airports />
</DeckGL>;

The React tree is flattened before deck.gl receives it. A view can contain React children for composition, but it does not scope its child layers to that view; use deck.gl's layerFilter. The renderer supplies the flattened view list to Deck, or to a Mapbox or MapLibre overlay, which renders it beside the map's own view.

6. Wrap your own classes​

For a custom layer, view, widget or effect, make a component once with createLayerComponent, createViewComponent, createWidgetComponent or createEffectComponent. No registration is needed:

import {createLayerComponent} from '@deck.gl/react';
import {FlowLayer as DeckFlowLayer} from './flow-layer';

export const FlowLayer = createLayerComponent(DeckFlowLayer);

When you already have an instance, for example from useMemo, pass it to a native element: <deckLayer layer={layer} />, <deckView>, <deckWidget> or <deckEffect>. See Native elements.

7. Combine JSX and layers only when needed​

DeckGL accepts the normal deck.gl layers prop as well as JSX layers. As in @deck.gl/react/legacy, the renderer appends the layers prop after the layers produced by JSX, so prop layers draw on top. This is useful while incrementally moving an existing deck.gl configuration to React, but all layers across both sources must have unique IDs.

import {ScatterplotLayer as DeckScatterplotLayer} from '@deck.gl/layers';

<DeckGL
  layers={[new DeckScatterplotLayer({id: 'existing-points', data: []})]}
  initialViewState={{longitude: -122.4, latitude: 37.8, zoom: 12}}
>
  <ScatterplotLayer id="react-points" data={[]} />
</DeckGL>;

8. Access the root instance when necessary​

Use onDeckChange to receive the root-specific Deck instance. Store it in React state if another component needs to react to the instance becoming available:

import {useEffect, useState} from 'react';
import type {Deck} from '@deck.gl/core';
import {DeckGL} from '@deck.gl/react';

function Map() {
  const [deck, setDeck] = useState<Deck | null>(null);

  useEffect(() => {
    if (!deck) {
      return;
    }

    // Connect imperative behavior to this root instance.
  }, [deck]);

  return (
    <DeckGL onDeckChange={setDeck}>
      <Airports />
    </DeckGL>
  );
}

The notification receives null when its root is cleaned up. It is not a callback ref: replacing only the callback does not reconfigure or unmount the root, although the replacement receives later lifecycle notifications.

Add a provider overlay​

Provider selection is an import-path decision. Use /mapbox for MapboxOverlay or /maplibre for MapLibreOverlay; install the matching @deck.gl package and create/configure the host map in your application. Store the overlay from onDeckChange in state and attach it to the map in an effect, so it is attached once per instance and detached during cleanup. See Attach the overlay to the host map for the lifecycle, and the Mapbox and MapLibre guides for complete examples.

Deck callbacks such as onClick are deck.gl event handlers, passed to the root or a layer, not React synthetic events.
